# AttackAgent Detect

Methods and tools for analyzing security execution traces through log normalization, behavioral comparison, trace-association research, and execution-mode evaluation.

## Implemented library methods
- Normalize Linux auditd SYSCALL / EXECVE records into trace JSONL while retaining event references.
- Rank candidate traces with command-token cosine, action-bigram cosine, or the ProcGrep procedure-frequency adapter. These scores describe behavior similarity and do not confirm a shared activity.
- Score Human / Agent execution mode with a local experimental detector when labeled training records use a matching capture format. Scores are not calibrated actor-identity probabilities.

## Separate research work
- Public CTF trace-association studies evaluate command and distinctive-artifact evidence. A same-task label is a retrieval proxy, not proof of the same operator, attack, campaign, or APT group.
- A mode-aware pair ranker remains a research prototype. Mode findings are limited by differences in how Human and Agent traces were collected.

Start with the repository examples. Check each method's status and evidence limits before applying it to other data.

Python API

Python API解析与排序
from pathlib import Path
from attackagent import TraceEvidence, load_auditd, rank_candidates

# 读取 auditd 日志（仓库中的格式示例）
traces = load_auditd(Path("examples/auditd/minimal.audit"))
print(traces[0].commands)  # ("curl", "grep")

# 对候选轨迹按命令相似度排序
query = TraceEvidence("query", "example-v1", "demo", ("curl", "grep"), ())
candidate = TraceEvidence("candidate", "example-v1", "demo", ("curl", "ls"), ())
for result in rank_candidates(query, [candidate], method="command_cosine"):
    print(result.trace_id, result.score)

示例使用手写的 auditd 格式样例和演示候选，输出的分数表示行为相似度。

本地识别器使用采集格式匹配的 Human/Agent 标注数据生成执行模式评分；行为排序可以独立调用。
