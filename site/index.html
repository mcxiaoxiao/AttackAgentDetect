# AttackAgent Detect

Open research prototype for analyzing whether execution mode is visible in command and action traces, and whether that signal improves behavior-based trace association.

## Input
- JSONL records with `trace_id`, `benchmark`, ordered `commands`, and coarse `actions`.
- Training records also need labeled `activity_id` and `mode` (`human` or `agent`).
- Linux auditd `SYSCALL`/`EXECVE` logs can be normalized from source. Sysmon is not supported; `script` classification has no labeled data yet.

## Output
- Human-like / Agent-like score with observed command evidence and an abstention reason.
- Candidate trace ranking by baseline similarity and mode-aware score.
- Scores are uncalibrated ranking/classification outputs, not probabilities of actor identity, common activity, or APT attribution.

## Current evidence
- 177 public CTF traces from 40 matched task groups; task identity is only a same-challenge proxy label.
- Mode prediction is confounded with capture pathway (human terminal input vs Agent tool-call records).
- A fixed split shows a small gain over one task-supervised ranker; five alternate splits average to no stable gain.

Run the source examples and inspect the JSONL schema in the repository before applying this prototype to other data.

Python API

Python API解析与排序
from pathlib import Path
from attackagent import TraceEvidence, load_auditd, rank_candidates

# 读取 auditd 日志（仓库中的格式示例）
traces = load_auditd(Path("examples/auditd/minimal.audit"))
print(traces[0].commands)  # ("curl", "grep")

# 对候选轨迹按命令相似度排序
query = TraceEvidence("query", "example-v1", "demo", ("curl", "grep"), ())
candidate = TraceEvidence("candidate", "example-v1", "demo", ("curl", "ls"), ())
for result in rank_candidates(query, [candidate], method="command_cosine"):
    print(result.trace_id, result.score)

示例使用手写的 auditd 格式样例和演示候选，输出的分数表示行为相似度。

本地识别器使用采集格式匹配的 Human/Agent 标注数据生成执行模式评分；行为排序可以独立调用。
