Agent 身份、行为与归因

Synthetic APTs: the Collapse of TTP-Based Attribution

🌟可做为我们的动机：论文实验显示，AI Agent 模仿不同组织时，行为趋同会让仅凭 TTP 做组织归因更难；对我们而言，关键是检验 Human 与 Agent 的执行方式会不会改变轨迹相似度和关联判断。若会，系统就不能把“行为相似”直接当作“同一执行者或战役”的证据。
①目标：检验 AI 代理模仿 APT 组织时，传统基于 TTP 的威胁归因是否仍可靠；
②方法：用同一攻击模型与框架配置成 5 个 APT 画像，在两个网络靶场中运行攻击，并观察防守结果和行为与官方 TTP 画像的匹配程度；
③结果：模拟的不同 APT 行为出现明显收敛，画像匹配精度约 55–80%；攻击表现受靶场环境影响很大，企业网实验被攻陷，军事网实验则被防住或陷入僵局；
④与本研究关系：提出核心动机——Agent 可能模仿不同组织，削弱仅凭 TTP 归因的可信度；本研究可先识别 Agent 参与，再检验它是否能校准归因证据。局限：单一攻击模型/框架，受控仿真结果不能直接外推到真实组织归因。 arXiv

数据核实 · 2026-11-01：全文可核对受控实验、TTP 对照表与提示设计，但本轮未定位到20次实验的独立逐会话原始日志归档，也没有 Human 对照。用于研究动机和条件设计；暂不列为可直接训练的数据集。全文与附录。

Trace

🌟作用：可作为命令序列分类的方法参照，说明命令及相邻命令组合能用于行为识别；它识别底层模型家族，我们关注执行方式识别与轨迹关联，标签任务不同。
①目标：从 AI 攻击代理的终端命令推测其模型家族，并尝试提取系统提示词；
②方法：先将终端命令序列转成 TF‑IDF 一元、二元特征，用线性 SVM 初步识别模型家族；再在沙箱中投放针对该模型的提示注入载荷，尝试诱导 Agent 输出系统提示词；
③实验：在 Docker Linux CTF 靶场测试 7 类模型和 3 种代理框架；基础实验是 7 类模型 × 3 种代理框架 × 每种组合计划跑 50 次，即 1,050 场；因部分会话崩溃或没有产生命令，最后保留 1,010 场干净会话。此外还跑了 1,018 场带提示注入的会话，合计 2,028 场。
④开放情况：没数据，论文称代码、评估脚本和复现笔记本已提供，完整数据集计划后续发布； arXiv

数据核实 · 2026-11-01：论文明确写明完整数据集稍后发布；评估代码指向匿名仓库，本轮该入口未能访问。2,028场是论文实验规模，不能当作已下载的公开样本量。当前作为词汇基线与格式参考，暂不计为现成数据。全文的数据开放说明 · 论文给出的代码入口。

CyBiasBench

🌟作用：现有工作中最贴近我们画像测验的可复用数据，可直接测 Agent、目标和攻击类型识别；但没有 Human 样本，不能检验 Human/Agent 识别。
①目标：检验不同网络攻击 Agent 是否稳定偏向特定攻击家族，以及提示能否改变这种偏好；
②方法：记录五个 Agent 对三个脆弱 Web 靶场的 HTTP 请求，比较自由选择与指定攻击家族条件，并标注攻击家族、目标和成功情况；
③实验：630 场会话（180 场自由选择、450 场指定家族）；公开数据含会话级统计和 277,135 条去敏请求级轨迹，带 Agent、靶场、条件、攻击家族、成功与请求顺序标签；
④数据复用：最适合直接做 Agent／目标／攻击类型画像识别，可按会话聚合并做留一靶场测试；无真人样本，且请求正文、请求头和精细时间已去除，不能直接测真人与 Agent 区分。数据和复现材料见 https://github.com/Harry24k/CyBiasBench。 arXiv · 数据与代码

数据核实 · 2026-11-01：已核对数据目录，并通过公开下载入口读取请求CSV表头：包含record_id、agent、target、request_index、HTTP方法/路径/状态及攻击家族等。可以做Agent侧画像和留一靶场验证；没有Human组，且HTTP请求不能改名成主机执行命令。实际数据文件 · 字段说明。

LIDAR（Who Is Behind the Harness?）

作用：展示用成对主动探针识别 Agent 底层模型的做法，可参考其配对测验设计；但任务是编码，且暂未核实有公开标注轨迹。
①目标：在编码 Agent 的执行轨迹中识别底层模型，审计模型替换后行为是否变化；
②方法：主动下发三组成对编码探针，观察编辑后验证、临时故障恢复、需求与测试冲突处理；用实例级和分布级轨迹特征识别模型；
③实验：36 个模型、7 个模型家族、2 种编码 Agent 框架；报告 Top-1 准确率约 88–95%，并做特征和探针消融；
④数据复用：论文描述的是主动探测方案，适合复刻成“同一目标成对任务”测验；目前未核实到可下载的逐会话标注轨迹，因此不计为现成数据集。论文：https://arxiv.org/abs/2609.28559。 arXiv

数据核实 · 2026-11-01：已核对全文中的探针和特征定义，未定位到作者提供的独立可下载逐会话轨迹入口。“36个模型”是实验设计规模，不是已获取的数据条数。适合作为主动探针和消融设计参考，暂不承诺直接复用训练数据。论文全文。

Known By Their Actions

作用：提供从被动 UI 事件识别浏览器 Agent 模型的思路；但跨网站泛化较弱，任务也不同于攻击终端行为。
①目标：检验网站能否只凭浏览器 Agent 的页面交互轨迹，识别背后的模型；
②方法：用网页端 JavaScript 被动记录点击、滚动、按键、焦点变化及操作间隔，再从行为序列训练分类器；
③实验：14 个模型、多个 Agent 运行环境与 4 类网页任务；报告最高 F1 约 96%。跨网站识别降至约 26–30%；时间延迟能扰乱原分类器，但用延迟数据重训后效果可恢复。
④数据复用：公开仓库提供采集与分类代码，并称发布标注轨迹；但我检查的仓库当前主要是 src/README，未确认原始会话数据随仓库提供。它的任务/网站标签可供类似实验设计参考；在确认数据文件可下载前，不把它算作可直接训练的数据集。 arXiv · 代码仓库

数据核实 · 2026-11-01：更新原“未确认数据”的判断：已找到并读取归档样例。src/traces.tar.xz是Git LFS指针，对应184,239,560字节的归档；本轮通过公开媒体入口读取2份会话JSON，确认含meta、model_name/model_family及dom_trace事件。全量会话数未统计。可用于浏览器Agent指纹与跨任务验证；未发现配套Human对照，也不属于攻击终端日志。LFS归档入口 · 实际归档下载。

ProcGrep

作用：可借鉴把操作流程表示为程序特征来识别 Agent；公开轨迹来自 SWE-bench 编码任务，不是攻击会话。
①目标：从编码 Agent 的完整操作流程识别 Agent 身份，并研究模型、任务和框架如何影响解题习惯；
②方法：将轨迹动作归纳为程序化词表和流程表示，比较轨迹结构，而不只看最终答案；
③实验：基于 SWE-bench 代理轨迹比较 10 个 Agent，按任务控制泄漏后识别准确率为 85.7%；相近发布时间模型及蒸馏师生模型的流程更相似；
④数据复用：可复用公开 SWE-bench 实验档案中的轨迹，含 Agent 身份与任务实例，适合做 Agent 分类和按任务留出验证；数据是编码任务轨迹，不是攻击行为或真人操作者数据。代码：https://github.com/hamidahoderinwale/procgrep；论文：https://arxiv.org/abs/2606.16988。 arXiv · 代码仓库

数据核实 · 2026-11-01：代码与底层公开编码轨迹来源可核对。例如SWE-rebench OpenHands数据页直接提供trajectory_id、instance_id、trajectory和tools字段。ProcGrep README所列spines入口本轮返回401，暂不承诺该预计算集可用；底层轨迹与模型/框架标签仍须逐来源核验。适合外域方法验证，没有Human攻击对照。代码与来源 · 已确认的底层轨迹。

Cross-Agent Campaign Attribution

作用：可借鉴结构和文本风格特征做跨会话关联；但公开数据的身份是合成 persona/campaign，不是真实操作者或 APT 组织。
①目标：把分散在多个 LLM Agent、彼此异步的攻击会话关联到同一潜在攻击战役；
②方法：从代理可见的工具调用结构、文本风格、时间和提示残留提取特征，计算会话对的战役相似度；
③实验：构造 SCD-v1 合成基准，含约 2,000 条带 persona／campaign 标签的会话，并提供合成数据与脚本；另有 OpenClaw、LangGraph 脱敏原生样例，原始原生日志未公开；合成基准 campaign linking AUC 0.82；
④数据复用：可复用来测“同一合成 persona／campaign 的跨会话关联”，也可借用结构、文风特征；标签是合成身份，不是真实操作者、组织或已知模型，不能当作现实人物画像识别数据。论文：https://arxiv.org/abs/2607.18826。 arXiv

数据核实 · 2026-11-01：全文称补充材料包含SCD-v1与脱敏派生记录，但本轮未定位到独立可下载的补充数据包；因此“论文称发布”与“本地已拿到”分开记录，暂不按可立即训练处理。其persona/campaign为合成标签，针对Agent的攻击会话也不能直接充当Human/Agent执行来源标签。全文与补充材料说明。

CVE-Bench

作用：提供可复用的真实漏洞靶场和目标，可据此新采集带 Agent、框架、CVE 标签的会话；论文未确认提供逐会话标注轨迹。
①目标：评估 AI Agent 利用真实 Web 应用高危漏洞的能力；
②方法：搭建包含真实 CVE 脆弱应用的隔离沙箱，运行攻击 Agent 并按是否成功利用漏洞评分；
③实验：40 个真实 Web CVE；论文评估 GPT-4o 与三种 Agent 框架，最高利用成功率约 10–13%；
④数据复用：适合复用靶机和漏洞目标，自己重跑并记录 Agent、框架、目标 CVE、会话轨迹与结果；未核实到论文实验逐会话轨迹及身份标签公开，因此不能直接拿来训练画像分类器。论文/基准：https://arxiv.org/abs/2503.17332。 arXiv · 会议版本

数据核实 · 2026-11-01：已核对官方仓库，提供漏洞任务、运行与评分工具，适合在统一日志条件下重采。README中的“data and code”不自动等于论文所有逐会话轨迹已公开；本轮未确认完整历史评估轨迹下载包，也没有Human对照。官方仓库。

攻击重建与关联中的行为证据

ATLAS、HOLMES 与 ATLASv2

作用：为系统行为建模和攻击事件重建提供先例，可参考如何把行为转成攻击阶段与关联证据；但不判断 Agent 或操作者身份。
ATLAS（USENIX Security 2021；未找到 arXiv 版本）从因果审计图序列恢复攻击故事；HOLMES 将溯源图信息流映射到攻击阶段，并将可疑行为关联为 campaign 信号。ATLASv2 是后续数据集扩展，不是 ATLAS 原论文。它们说明系统行为可用于攻击调查，但关注事件重建，而非 Human / Agent 识别。 ATLAS 正式来源 · HOLMES arXiv · ATLASv2 arXiv

数据核实 · 2026-11-01：ATLASv2论文明确给出公开数据与REAPr攻击进程标签入口，含Windows安全、Sysmon等日志，可支持溯源图适配和攻击重建。真人日常背景活动不等于Human攻击会话；数据没有Agent组，不能单独做浓度实验。原ATLAS与HOLMES也不提供Human/Agent执行来源对照。ATLASv2数据 · 攻击进程标签 · 开放说明。

HERCULE 与 OSTINATO

作用：可参考用日志图社区结构关联多阶段攻击活动；但它不区分 Human/Agent，也不识别具体操作者。
HERCULE（ACSAC 2016；未找到 arXiv 版本）通过相关日志图上的社区发现重建多阶段攻击故事；OSTINATO 比较跨主机溯源图行为以关联相似攻击活动。它们是行为关联的先例，但都未评估人类与 AI 执行方式是否改变关联判断。 HERCULE 正式来源 · OSTINATO arXiv

数据核实 · 2026-11-01：OSTINATO使用OpTC和DARPA TC日志及红队记录构建关联评估，完整输入包含跨主机进程/对象与溯源关系。可参考关联基线，但不能仅给命令名就声称复现原算法。本轮未核实到其完整派生配对标签下载包；这类历史日志也不能默认全部标成Human攻击。OSTINATO数据与真值说明 · DARPA TC官方数据入口。

POIROT 与 SFM

作用：可参考把威胁情报中的攻击行为与系统记录对齐；但它做的是行为检索，不提供执行者身份标签。
POIROT（2019）将威胁情报提取的攻击行为图与内核审计日志生成的溯源图对齐；SFM（2024）把因果审计子图与已知 campaign 模式匹配。两者用于在系统记录中检索威胁行为，不提供 Human / Agent 标签，也不回答同题轨迹是否代表同一执行者。 POIROT arXiv · SFM arXiv

数据核实 · 2026-11-01：POIROT与SFM依赖事件对象、因果关系或TTP/子图，而不仅是轨迹词汇。SFM所引用的SAGA有公开模拟日志版本，可作关联方法参考；情报画像/攻击进程标签均不等于Human/Agent标签。POIROT · SAGA数据。

本研究的实验观察

在 CTH 来源留出中，训练侧排除已知重合题名后，条件化指纹将任务宏 BA 从 52.0% 提高至 56.7%，漏关联下降、误合并上升；同一方法在 Antieval 来源留出中 BA 下降。两者使用同题代理标签，区间均属探索性结果。 查看多来源比较。

AIT 识别实验使用实际 audit 时间，并区分任务组与采集来源组留出；任务工作流和采集路径仍与执行方式标签混杂。 查看识别结果。

研究选择：Trace、ProcGrep、LIDAR 和 Known By Their Actions 证明具体模型或 Agent 候选集内可以从行为中识别系统特征；Cross-Agent 已研究 Agent 会话关联。本文不否认这些方向，而是聚焦日志可得性：调查者通常不一定知道具体执行栈，也未必能够主动探测或接入统一沙箱。我们测试同一组可解释日志特征能否支持执行方式分析，并作为命令／请求证据的关联补充。当前数据的“同题”“同提示条件”“同目标”仍是检索代理，不能验证真实攻击活动、campaign 或操作者关系。

跨来源采样的意义与限制：CTH、AIT、Honey 和 CyBiasBench 提供不同任务和观测格式。多来源采样用于检验表示对异构输入的适配并扩大覆盖，不自动构成泛化贡献；所有来源各自评估，来源留出、字段可见性和标签定义均在方法页逐项列出。本文的现有结论限定于这些已公开任务／条件代理。
