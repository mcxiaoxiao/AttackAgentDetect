\section{Motivation and research question}

Attack investigation links dispersed events into activity candidates before analysts make higher-level judgments about campaigns or organizations. This is an established computational task: HOLMES correlates suspicious information flows in host-audit traces to produce campaign evidence; OSTINATO compares behavior and TTPs across hosts; POIROT and ActMiner align CTI-derived attack graphs with provenance graphs; HERCULE, ATLAS, and FALCON reconstruct multi-stage attack stories from correlated logs \cite{holmes,ostinato,poirot,actminer,hercule,atlas,falcon}. These methods use command or event sequences, TTPs, entity relations, and causal structure as evidence. Their evaluation targets differ, but each demonstrates a concrete role for behavioral association in investigation. Practitioner frameworks likewise track activity clusters before assigning named actors \cite{unit42}.

Execution mode is now part of the observable threat narrative. Anthropic's 2025 report describes human operators coordinating Claude Code agents and MCP tools across a multi-stage campaign; MITRE records the activity as Campaign C0062 \cite{anthropic,mitrec0062}. This motivates a testable extension to behavior-based correlation: execution mode may contextualize the behavior evidence used to connect activity fragments. If mode changes the representation of a shared activity, a ranker may split related traces; if separate activities share an execution template, it may over-link them. We test whether a mode score adds retrieval information beyond behavioral similarity. The study does not assume either error mechanism in advance.

\section{Data and protocol}

We use the pinned CC BY 4.0 release of Cyber Task Horizons (revision \texttt{178c0da1800f9\allowbreak c07311e1b8d\allowbreak 6c61dd8104e7b\allowbreak 4e7b4ae}) \cite{cth}. It contains task-based CTF evaluations and expert terminal recordings. We select InterCode-CTF, CyBench, and NYU CTF Bench, the three suites with overlapping human and Agent task records. The resulting corpus has 177 non-empty traces in 40 benchmark-qualified task groups: 57 expert terminal records and 120 Agent tool-call records. InterCode-CTF contributes 27 groups (40 human, 81 Agent), CyBench 6 (8 human, 18 Agent), and NYU CTF Bench 7 (9 human, 21 Agent).

Human records are terminal-input transcripts; Agent records are structured bash tool calls. For both, we extract allowlisted command names and coarse action categories. Prompts, task descriptions, outputs, model names, timestamps, and paths are excluded; 300 Python calls are omitted from primary features. The release instructs human experts not to use AI, but remote collection cannot independently verify this. The labels therefore describe released trace sources, not independently adjudicated decision-maker identity.

The primary protocol uses three benchmark-stratified outer folds grouped by benchmark/task, with seed \texttt{20261030}. Every query is ranked against all other held-out traces from the same benchmark and fold, with no mode filtering; the mean gallery contains 29.325 candidates. Same benchmark/task denotes a same-challenge retrieval proxy. It is not a shared intrusion, activity, campaign, or actor label. Five additional seeds estimate split sensitivity. Task groups are the unit of metric aggregation and bootstrap resampling. We report task-macro \Hit, mean reciprocal rank (MRR), Recall@5, and nDCG@5. Intervals use 5,000 paired benchmark-stratified task-cluster bootstrap draws conditional on fitted folds.

The behavior ranker combines command cosine, ordered action-bigram cosine, ProcGrep BPE/Jensen--Shannon similarity, and command-length similarity. A task-supervised ranker learns from same-task versus different-task pairs. The mode-aware ranker adds execution-mode scores generated out of fold within each training partition. Pair labels depend only on task identity; test labels and source metadata are excluded from inference. ProcGrep is a pinned third-party adaptation, not a method introduced by this project.

\section{Results}

The mixed gallery gives a random-ranking \Hit{} of 0.189. Command cosine reaches 0.600; ProcGrep reaches 0.594; the task-supervised behavior ranker reaches 0.571. Mode-aware ranking is highest on the fixed primary split at 0.607, a +0.036 paired change over the task-supervised ranker (95\% CI [+0.006, +0.069]). Against command cosine, the change is +0.008 (95\% CI [−0.046, +0.059]). Across the five alternate splits, the mode-aware minus task-supervised change averages −0.007 (95\% CI [−0.026, +0.012]). The positive primary-split estimate therefore does not persist across the split-sensitivity check.

\subsection{Association errors at a training-only threshold}

Retrieval metrics do not show the errors made when the system decides whether to connect a pair. We therefore evaluate pairwise decisions under a nested protocol: each outer training fold supplies three inner task-held-out folds for threshold selection; the outer test tasks remain untouched. Each method receives its own threshold, selected to maximize task-macro balanced accuracy on inner out-of-fold pairs. A test pair is linked when its score meets that threshold. We compare command cosine, the task-supervised behavior ranker, its mode-aware extension, and a command-length control. The target is same-task matching within the released CTF benchmarks, not real attack-activity matching.

The mode-aware ranker reaches task-macro balanced accuracy 0.669 (95\% task-cluster CI [0.611, 0.722]), compared with 0.612 [0.568, 0.657] for the behavior-only ranker. The paired increase is 5.7 percentage points [3.4, 8.1]. Against command cosine, however, the increase is 0.6 points [−4.1, 4.8], leaving no clear gain over this simpler baseline.

The pair-type breakdown shows where the mode score changes decisions. Relative to behavior-only ranking, it lowers the false-split rate for same-task H--Agent pairs from 0.317 to 0.191 (−12.6 points, 95\% CI [−17.7, −7.6]) while raising the false-merge rate for different-task H--Agent pairs from 0.387 to 0.472 (+8.4 points, [3.4, 13.2]). Execution-mode context therefore reduces one cross-mode proxy error while increasing another; the result supports conditional use of this signal, not a universal correction.

\section{Conclusion}

Prior attack-investigation systems connect host behavior through event sequences, TTP patterns, entity relations, and causal provenance. We test execution mode as additional context for these associations. In the public CTF proxy evaluation, mode-aware ranking reduces same-task cross-mode false splits but increases different-task cross-mode false merges; its overall balanced accuracy is not clearly above command cosine. These outcomes identify a specific tradeoff for a controlled follow-up: repeated human, script, and Agent executions under one sensor pipeline, labeled with independent activity identifiers, so both errors can be measured at the activity level.
