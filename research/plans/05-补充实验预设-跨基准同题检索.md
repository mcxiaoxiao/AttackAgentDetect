# 补充实验预设：跨基准同题轨迹检索

> 预设时间：2026-10-29 06:05（北京时间）。这是既有 InterCode-CTF 结果公开查看后的补充探索，不能称为预注册或确认性分析。本文档先于 CyBench、NYUCTF 新轨迹内容的检查与指标计算写定。

## 研究问题与竞争解释

现有公开轨迹能否支持一个更窄且可检验的问题：在同一安全挑战题内，命令行为表示对人类轨迹和 Agent 轨迹的检索效果是否相近？如果跨执行模式的同题检索低于同模式检索，是否可能是日志表示/交互方式变化的信号？

竞争解释：

1. **执行行为改变：** 同题的人类与 Agent 轨迹在命令组成或顺序上不同，跨模式检索相对困难。
2. **任务难度/求解路径差异：** 同一题有多条合理路径；相似度不能代表行为关联，差异不由执行模式导致。
3. **采集模态混杂：** 人类输入从终端录制，Agent 输入从工具调用记录；分类或相似度受记录方式影响。
4. **题目分布捷径：** 指标主要利用 benchmark 或题型差异；需在同 benchmark 的不同题目上构造困难负例。
5. **抽样波动：** 任务少、重复轨迹数不平衡导致点估计不稳定。

此处“同题”只表示基准任务 ID 相同，不表示同一攻击活动、同一行为脚本、同一操作者或同一 APT 组织。

## 数据与范围

- 固定上游版本：`lyptus-research/cyber-task-horizons-data`，commit `178c0da1800f9c07311e1b8d6c61dd8104e7b4ae`。
- 核心样本：原有 InterCode-CTF 数据；新增同源发布中的 CyBench 和 NYUCTF 专家终端记录及 Sonnet 4.6、Opus 4.6、GPT-5.5 Agent 评测记录。只选择预先列明的 benchmark/eval-set，不根据本实验得分挑选模型或题目；原始记录做 LFS SHA-256 验证。
- 任务交集：仅纳入同一 `benchmark/task_id` 下至少有一条人类和一条 Agent 轨迹、且预处理后有可比较命令的任务。保留任务来源和各类样本数；不得将不同 benchmark 的相同裸 task ID 合并。
- 可见输入：人类终端输入行与 Agent `bash` 工具调用中的 shell 命令；排除提示词、内部推理、模型名、任务描述、工具输出、终端时间、路径、答案和评分。Agent 的 Python 工具代码不读入主分析；其调用次数单独报告并在可行时做“每次 Python 调用映射为一个 execute 动作”的敏感性检查。
- 不执行数据中出现的命令或脚本。只解析并保存命令头/固定动作类别，不提交原始会话日志。

## 分析 A：同题行为检索

**独立单位：** `benchmark/task_id`；轨迹和轨迹对都是嵌套观测，不作为独立样本。

**固定表示：** (a) 命令 unigram 余弦；(b) 有序相邻命令 bigram 余弦；(c) 粗粒度动作类别的有序 bigram 余弦；(d) ProcGrep 行为分布相似度，作为局部程序模式对照。所有表示和相似度不得使用模型名、题目文字或答案。ProcGrep 的词表只从训练任务拟合；测试题不参与拟合。

**匹配任务：** 分别构造人→Agent、人→人、Agent→人、Agent→Agent 查询。正例是同一 benchmark/task_id 下候选轨迹，负例是不同 task_id 的候选轨迹；主要结果限定负例为同一 benchmark 的不同题目，以排除跨 benchmark 的容易差异。题目内先对查询结果取平均，再对独立任务等权宏平均。报告每种方向的可用任务数、正例/负例数、Recall@1、MRR、查询 AUC 及任务级 95% bootstrap 区间；并给出随机排序基线。每次 bootstrap 重采样完整任务簇，绝不重采样单独的轨迹对。

**主要比较：** 人–Agent 检索与可估计的人–人、Agent–Agent 检索之间的任务宏平均差值及任务簇 bootstrap 区间。人–人若任务内重复专家记录不足，则只作描述，不与其余组作推断性对比。所有同题结果都只解释为任务检索，不解释成真实活动关联。

## 分析 B：执行模式分类与负控

- 外层使用按 `benchmark/task_id` 分组的 5 折交叉验证；同题轨迹不能跨折。主分类器固定为 TF-IDF 命令 unigram/bigram + 类别平衡逻辑回归（`C=1`），不根据测试结果调参。
- 预先列出的负控特征：仅命令数、仅粗粒度动作比例；它们与主分类器使用完全相同的任务折。另报告不同 Agent 模型上的 Agent 召回率，并做留一模型家族测试；任何高分都只能称为“此公开数据中专家终端记录与指定 Agent 工具调用记录的区分”。
- 报告混淆矩阵、balanced accuracy、macro-F1、precision/recall、ROC-AUC；置信区间按任务簇 bootstrap。任务数量不足或某折缺类别时，如实降低折数并记录，不复制轨迹制造样本量。
- 结果不具备同一传感器、同一执行接口、脚本类及确证人类未使用 AI 的控制，因此不得将分类分数解释为部署环境中的主体识别准确率。

## 分析 C：参与信息对关联的增量

只作次要、探索性检验。以同一 `benchmark/task_id` 作为暂用匹配标签，对比基于相似度的跨折基线与增加执行模式信息后的成对分类。任务分组切分；测试折不得与训练折共享任务。报告阈值无关 AUC 为主，并按训练折确定阈值后报告误拆分/误合并率。参与标签的 oracle 结果与折外预测标签结果分开；增加的特征和参数数必须公开。若参与信息没有在多个 benchmark 的同题代理任务上稳定改善误差，则不写“识别后恢复关联”。

## 解释规则与停止条件

- 只有跨 benchmark/task 的独立任务簇提供样本量；更多模型轨迹只增加每题观测，不会等比例增加独立样本。
- 只有跨模式检索显著低于至少一个同模式对照、困难负例仍成立、且区间足以排除微小差异时，才可把结果写成“在这些挑战题轨迹中观察到执行模式相关的检索差异”。本轮以区间和效应大小为主，不将单一 p 值当作证明。
- 如差异消失、区间过宽、不同表示方向相反，结论应为证据不足或结果依赖表示。
- 无论结果如何，不能从 CTF 同题代理任务推出真实 APT 活动/组织归因会误并或误拆。那需要同传感器下人类、固定脚本和 Agent 重复执行有独立活动真值的受控实验。

## 实际执行记录（2026-10-29）

扩展实验已完成，原型和逐题结果见 [`../reports/06-原型与跨基准实验结果.md`](../reports/06-原型与跨基准实验结果.md)。实际纳入 177 条非空轨迹和 40 个同基准同题任务组，外层五折按任务留出。实现和结果文件为 `attackagent/prototype.py`、`scripts/run_crossbenchmark_experiments.py`、`scripts/run_mode_aware_association.py`。

补充的模式感知排序器使用命令 unigram、动作 bigram、折外模式概率及其交互项。模式识别在外层训练任务内再次分组交叉拟合；测试任务只接收训练模型输出。模式排序器对 Human→Agent Recall@1 的点估计增加 0.068，但配对 95% 任务簇区间为 [-0.012, 0.191]；MRR 和查询 AUC 增量区间也跨零。Human→Human 方向出现下降。故当前不满足“识别后恢复关联”的判据，也没有支持“Agent 导致关联失效”的证据。所有具体数值、不同检索方向、基准拆分和不确定性见报告及 `results/mode_aware_association.json`。

补充实现修复了检索 MRR 对并列候选的处理：现在对并列排名位置的倒数取期望，而不是先取平均排名再求倒数。原始轨迹已按文件大小与 SHA-256 核验；新增原始日志仍未纳入版本控制。
