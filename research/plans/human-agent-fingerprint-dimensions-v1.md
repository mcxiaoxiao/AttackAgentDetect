# Human/Agent 安全执行画像：维度重设计 v1

日期：2026-11-01。状态：候选测量规范草案，未验证分类有效性，未替换旧特征实现。主目标为会话级 Human/Agent 执行来源识别及可解释画像；不研究幕后人员或组织身份，不采用 SVD、HOSVD 或 TSA。

**本轮收缩决议（2026-11-01）：** 以下六组21项保留为完整调研候选。实际主实验依据常见执行日志收缩为 F01–F07、F12 共8项；F08/F09仅作字段足够时的扩展，其余候选暂缓。Linux execve 的 syscall 返回值不能当作程序最终退出状态；进程启动间隔不能当作反馈到决策的停顿。完整的新主稿见 `../paper/human-agent-fingerprint-main.tex`，本轮进展见 `../reports/human-agent-fingerprint-round1-progress.md`。

## 1. 设计原则

从攻击执行过程的可观察行为出发，重新定义六组、21 项候选标量。数量由定义得到，不以保留旧 24 项为目标。文献启发不等于指标已被证明可区分 Human/Agent；所有效应方向均待验证。

画像有三个不同组成：21 项标量候选；动作分布及转移图；按事件顺序绘制的过程热力图。图中每个动作类别或每条边不能与标量候选的维数混算。最终用于识别的指标在开发阶段检查覆盖、冗余及稳定性后固定，再开展独立测试。

区分人自主选择操作的会话和 Agent 根据反馈生成操作的会话。执行命令的系统进程相同并不决定标签；固定脚本和无法明确标注的人机混合会话另存，不强行作为任一类训练真值。

## 3. 最小事件与采集契约

1. 基础事件：session_id、单调事件序号、规范化命令名、动作类别、原事件引用。统一记录实际动作和解析覆盖；Agent 专属外壳命令不得直接变成标签捷径。
2. 命令构造：execve argv 或可还原的完整提交命令。管道、条件链和循环需要 shell AST/提交内容；只靠 argv 不能完整恢复 shell 语法。
3. 反馈：操作完成事件、返回码及其对应命令；非零返回码不自动等同于攻击失败，返回零也不自动表示利用成功。
4. 资源：命令涉及的文件、目录、网络对象及访问顺序。仅用于会话内相同对象识别和资源类别；完整路径、主机名、flag 和运行专属 ID 不直接作为身份特征。
5. 节奏：动作提交、开始、结束及反馈可用时间，时钟和精度一致。后台进程和并发动作需明确配对；不能把执行耗时当成决策停顿。

采集接口、模型名、框架、真实标签和任务 ID 保存在评估侧。命令数、有效转移数、总时长、未知动作数、字段覆盖与解析失败为质量/控制字段，不混入“行为特质”解释。

## 4. 六组、21 项候选标量

设命令名序列为 c1…cn，动作序列为 a1…am。所有比例给出有效事件数；分母为零记缺失。无法从当前输入观测的指标记 unavailable，不记零。

### A. 工具选择（3 项）

| ID | 指标 | 定义 | 字段 | 依据 |
|---|---|---|---|---|
| F01 | 命令词汇多样度 | 不同命令名数 / n | 命令名 | AIT 词汇统计适配 |
| F02 | 命令使用熵 | −Σ p(c) log2 p(c) | 命令名 | AIT/ProcGrep 分布描述适配 |
| F03 | 主导工具占比 | max p(c) | 命令名 | 集中度统计；本项目描述候选 |

这些指标描述工具分配，不预设人类或 Agent 一定更丰富。多样度和熵受观测长度影响，必须同时做统一观测预算和长度敏感性检查。

### B. 动作组织（4 项）

| ID | 指标 | 定义 | 字段 | 依据 |
|---|---|---|---|---|
| F04 | 动作切换率 | 相邻不同动作的数量 / (m−1) | 有序动作 | 序列结构适配 |
| F05 | 下一步条件熵 | H(A_next given A_current)，按有效相邻转移的经验分布计算 | 有序动作 | HABITS 条件熵启发；ProcGrep 动作视角 |
| F06 | 连续操作集中度 | 最长同动作连续段长度 / m | 有序动作 | 本项目序列描述 |
| F07 | 两步组合复用率 | (有效动作二元组数 − 不同二元组数) / 有效二元组数 | 有序动作 | Trace/ProcGrep 组合模式启发；此汇总公式为项目定义 |

F04 与“相邻动作重复率”完全互补，因此只保留 F04，避免重复计算同一证据。完整二元转移频率作为图和独立序列基线保存，不假装四个标量能保留所有顺序信息。

### C. 命令构造（4 项）

| ID | 指标 | 定义 | 字段 | 依据 |
|---|---|---|---|---|
| F08 | 参数数量 | 每次调用中除可执行文件外 argv 个数的中位数 | argv | AIT 命令复杂度适配；Trace 参数信号启发 |
| F09 | 选项使用比例 | 含可识别 CLI 选项的调用数 / argv 可解析调用数 | argv/选项解析 | AIT flags 统计适配；不把负数或文件名中的连字符当选项 |
| F10 | 管道与条件链比例 | AST 含管道、&&、|| 或顺序链的提交数 / AST 可解析提交数 | 提交命令/shell AST | AIT chained-command 思路适配 |
| F11 | 批量执行比例 | 含循环或多个实际命令的提交数 / 可解析提交数 | 提交边界、shell AST | 本项目假设；框架强制批处理可能产生混杂 |

命令来源按相同提交粒度比较，剥离已知 harness 包装但保留剥离审计。引号内字符串不作为 shell 结构符。F10/F11 相关但不相同，须做组内冗余审计。

### D. 重复与反馈响应（4 项）

| ID | 指标 | 定义 | 字段 | 依据 |
|---|---|---|---|---|
| F12 | 相邻工具重复率 | 相邻相同命令名数 / (n−1) | 有序命令名 | AIT 重复行为适配；不能解释为失败重试 |
| F13 | 非零反馈后原样再执行比例 | 对可配对的非零返回事件，下一次决策对同资源提交相同命令与参数的比例 | 返回码、提交/反馈配对、资源、完整命令 | 本项目反馈响应假设 |
| F14 | 非零反馈后参数修订比例 | 同样的合格反馈事件中，下一次决策保持资源和工具但改变参数的比例 | 同上 | 本项目反馈响应假设 |
| F15 | 非零反馈后换工具比例 | 同样的合格反馈事件中，下一次决策针对同资源更换工具的比例 | 同上 | 本项目反馈响应假设 |

“下一次决策”排除自动包装/清理动作，指同一会话收到反馈后的下一次可归属操作；并发反馈无法归属时缺失。F13–F15 共享分母且可能相关，不能视为三份独立证据；没有合格反馈时均为缺失。它们测量可见响应，不宣称读到了规划、推理或自主性。

### E. 资源探索与回访（3 项）

| ID | 指标 | 定义 | 字段 | 依据 |
|---|---|---|---|---|
| F16 | 资源探索广度 | 会话内不同资源数 / 可识别资源的访问事件数 | 资源标识及访问事件 | HABITS 导航视角的场景适配假设 |
| F17 | 间隔回访比例 | 当前访问对象此前出现、且紧邻上一次访问对象不同的事件比例 | 有序资源访问 | 本项目回访假设 |
| F18 | 资源范围切换率 | 相邻可识别访问在规范化目录范围/资源类别间切换的比例 | 资源路径结构/类别 | 本项目探索范围假设 |

资源粒度（文件/目录/URL）按各适配器固定；不将文件日志与 HTTP 日志的比例直接合成同一个模型。不用真实靶标名称进行身份识别。资源广度不等于攻击目标覆盖率，回访不等于犹豫或失败。

### F. 执行节奏（3 项）

| ID | 指标 | 定义 | 字段 | 依据 |
|---|---|---|---|---|
| F19 | 反馈到下一次操作的间隔 | 同一会话内，反馈可用到下一次可归属提交之间有效间隔的中位数 | 反馈/提交时间 | AIT timing、HABITS 节奏启发；不是人的真实思考时间 |
| F20 | 间隔离散度 | 有效间隔 IQR / median；median=0 时缺失并保留时间精度信息 | 同上 | 稳健节奏统计；项目定义 |
| F21 | 间隔突发性 | (标准差−均值)/(标准差+均值)；分母为零时缺失 | 同上 | HABITS burstiness 定义适配 |

节奏作为独立扩展模块。模型服务延迟、网络、harness 和硬件都可能产生信号；主实验必须报告移除节奏模块的结果，不用“快就是 Agent”的先验规则。已去掉精细时间的数据不计算这些指标。

## 5. 当前实现的可用性

现有 TraceEvidence 仅有命令名、动作、事件引用和质量信息。因此 F01–F07、F12 共 8 项原则上可由当前序列实现；这不表示当前函数已经输出全部 8 项，F05 等需要新增实现和定义检查。

其他 13 项需要补充 argv、提交内容、反馈、资源或时间字段。不得用命令名序列伪造这些观测，也不能给 Human 和 Agent 使用不同采集能力后将缺失模式当成指纹。首轮效果分析应明确区分 8 项共同可观测核心、各独立扩展模块及字段完整子集，完整报告可用会话覆盖率。

旧版 gzip 比、命令/动作多组二/三元重复统计不再全部作为默认主特征。命令数量与短轨迹标记移到质量和长度对照；旧特征仍保留为历史比较，不覆盖原结果。

## 6. 画像展示

- 总体画像：六组候选的原始数值、训练参考分布位置、有效分母与可用性；无数据的组显示“未采集”，不显示低分。
- 动作热力图：按事件窗口展示动作分布，允许不同长度轨迹有不同窗口数；不是固定四阶段，也不自动命名为侦察、利用等攻击阶段。
- 动作转移图：动作二元组的频率与代表性证据片段。
- 反馈示例：只在具有完整反馈链时展示“返回非零 → 下一次具体操作”，不展示模型编造的恢复叙述。
- 识别结果与依据：预测标签/不确定、分组贡献和对应事件引用；分类结果独立于原始测量，不能回填为画像事实。

## 7. 怎样选出真正的指纹特征

1. 先检查每项定义、字段覆盖、重复值和样本内分母。明确短会话不可估的转移/节奏统计；不能将缺失一律填零。
2. 使用相同任务和相同采集契约下的 Human/Agent 对照，按完整会话和任务分组留出；能够取得人员/Agent 系统标识时另做来源留出检查。
3. 先比较长度单独基线、命令词汇 unigram/bigram 基线和可解释特征模型，确定收益是否超出工具词汇与记录规模。
4. 分别评估六组单独使用和逐组移除，使用相同分类器与分折；在开发数据中用分组置换和重复划分检查贡献稳定性。相关特征一起审计，不把单次重要性排序当固有规律。
5. 同时报告 Human 被误判为 Agent 的比例和 Agent 漏检率；低误报工作点是否可估取决于独立 Human 会话数量。所有阈值与特征筛选只用训练/开发数据，最终特征清单版本化后再测试。
6. 做统一事件预算、移除节奏、屏蔽任务专属资源名、缺失模式/采集来源诊断。完整会话与固定前缀结果分别解释，避免只留下长会话或成功会话。

采集管线可用性和候选特征的统计判别力是两项不同结论。最终学术主张应指出哪些维度在什么任务、来源和观测条件下有稳定贡献，不能把六组候选都提前称为有效 Agent 特征。
