\label{app:data}

The three selected Agent sources are Claude Sonnet 4.6, Claude Opus 4.6, and GPT-5.5, with 40 retained traces per model. For dated model-evaluation files, the latest available attempt per benchmark, model, and task is retained; otherwise the release's complete evaluation file is used. A human trace is recovered from recorded terminal `.input` events. An Agent trace is recovered from structured `bash` tool-call arguments. The Cyber Task Horizons collection launches human and Agent work in the same task containers, but the released trace interfaces differ; this subset is not common-schema host telemetry. Human participants were instructed not to use AI, although the remote study could not independently verify every session. Accordingly, the experimental labels identify the release's record source rather than a ground-truth human decision process.

After parsing, the analysis contains 57 human and 120 Agent records. The 300 Python tool calls in the selected Agent traces are excluded from the primary representation. We retain only allowlisted command names and their coarse action categories; prompts, task descriptions, outputs, answers, model identifiers, timestamps, and paths are removed before feature construction. The dataset measures whether trace representations retrieve another record of the same benchmark task. It does not provide labels for a common operator, intrusion, activity, or campaign.

\section{Feature construction and evaluation protocol}
\label{app:protocol}

\paragraph{Observed representation.} Human traces contribute recorded terminal command lines. Agent traces contribute command names from \texttt{bash} tool calls. The association baselines use command unigrams, adjacent ordered command bigrams, or adjacent bigrams over coarse action categories. The ProcGrep baseline represents local command patterns using the vendored \href{https://hamidah.me/procgrep/}{ProcGrep} implementation. The command vocabulary, TF--IDF weights, and ProcGrep tokenization are fitted on outer-fold training tasks only. No task prompt, task title, answer, model identifier, output text, timestamp, or file path enters the retrieval features. The 300 Python tool calls in the selected Agent traces are excluded from the primary representation.

\paragraph{Execution-mode head.} A class-balanced logistic-regression model consumes TF--IDF command unigrams and bigrams. For the standalone classification baseline, each task is assigned wholly to one of five outer folds. The negative controls use (i) log command count plus coarse action proportions and (ii) benchmark identity alone. Each control uses the same task folds. The predicted score separates the two dataset trace labels; it is not calibrated as a probability that an unknown real-world operator is an Agent.

\paragraph{Association prototype.} The similarity-only pair ranker combines command-unigram cosine similarity with ordered action-bigram cosine similarity. The mode-aware ranker adds each endpoint's execution-mode score, the score difference, and interaction features. Positives share a benchmark and task ID; negatives use another task within the same benchmark. Training pairs are balanced and task-weighted. In each outer fold, mode scores for training pairs are generated by inner task-grouped out-of-fold prediction; held-out pairs use the model trained without their task. The oracle diagnostic substitutes ground-truth mode labels at inference and is not a deployable system.

\paragraph{Ranking metrics and intervals.} \RecallAtOne is the fraction of queries whose positive task ranks first; ties at the top receive fractional credit. MRR averages the reciprocal rank of the positive task, taking the expectation over a uniform random ordering of exact ties. Query AUC is the probability that a positive task outranks a negative task, with half credit for ties. Metrics are first averaged within each independent task group, then macro-averaged across the three benchmarks. The random \RecallAtOne baseline is the reciprocal of the number of candidate task groups in the query's benchmark. Each 95\% interval uses 5,000 bootstrap replicates: task groups are sampled with replacement within each benchmark, benchmark strata are retained, and the three benchmark means receive equal weight. Paired intervals resample the same task groups for both rankers before taking their difference.

\section{Specificity controls and candidate-gallery sensitivity}

\section{Interpretation scope and next experiment}
\label{app:scope}

The positive retrieval target is a shared CTF task ID. It is not an independently verified shared intrusion, activity, campaign, or organization. The mode-classification labels identify expert terminal records and selected Agent tool-call records, and are therefore inseparable from the logging path in this release. The current evidence supports a reproducible benchmark question about mode-conditioned trace association; it does not estimate real-world APT attribution accuracy.

The next decisive experiment should replay matched defensive sandbox tasks under four conditions: human operation, fixed scripts, human-supervised Agent execution, and goal-directed Agent execution. All conditions should use the same host and network telemetry, task snapshots, and logging stack. Independent run IDs should define within-activity positive fragments; distinct runs with similar tools and objectives should provide hard negatives. Activity-grouped splits should hold out operators, task templates, and runs. This design would estimate whether execution-mode features alter association errors when behavior logs are collected under equivalent conditions.

\section{Conditional mode-label permutation diagnostic}
\label{app:permutation}

The post-hoc diagnostic used 999 permutations. For each outer fold, only training labels were shuffled within each benchmark--task group; task-group folds, per-task training label counts, held-out labels, pair ground truth, candidate sets, and sampled association pairs remained fixed. The nested task-OOF mode head and association ranker were refit for every permutation. Fixed evaluation reproduced the observed result with zero metric difference before permutations were run. This setup asks whether the observed increment is unusual relative to label assignments preserving task-level class composition within the present release. It does not randomize instrumentation, operator behavior, or model involvement and does not create exchangeability by design.

The figure-generation script reads only the versioned aggregate JSON results and writes vector PDF masters plus 300-dpi PNG previews to \texttt{results/figures/} and \texttt{paper/figures/}. The raw public traces are downloaded locally, verified by the manifest hashes, and excluded from Git. Primary machine-readable outputs are \texttt{results/crossbenchmark\_exploration.json}, \texttt{results/mode\_aware\_association.json}, \texttt{results/specificity\_controls.json}, and the corresponding task-level CSV files. The figure source is retained at \texttt{scripts/generate\_paper\_figures.py}.
