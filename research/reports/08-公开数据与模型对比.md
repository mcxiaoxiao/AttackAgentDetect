# 公开数据、模式识别基线与证据边界

**状态：** 2026-10-29。本文区分已运行结果、仅完成来源审计的数据，以及尚未运行的 API 比较。

## 为什么把执行方式放进活动画像

威胁情报需要把“哪些攻击属于同一 Campaign”和“哪些 Campaign 属于同一 Intrusion Set”分开表达。STIX 2.1 将 Campaign 定义为围绕目标和时间组织的一组恶意活动，将 Intrusion Set 定义为被认为由同一组织策划的相关行为与资源；Campaign 到 Intrusion Set 的归属是单独关系。执行方式因此可以作为描述一项活动如何被操作的上下文维度，供行为证据解释和关联使用，而不是组织身份的替代标签。[STIX 2.1](https://docs.oasis-open.org/cti/stix/v2.1/os/stix-v2.1-os.html)

这不是纯假设的未来场景。MITRE 将 2025 年一次间谍活动记录为 Campaign C0062，描述人类操作者借助 Claude Code Agent 与 MCP 工具执行侦察、漏洞利用、横向移动和数据收集等工作。[MITRE ATT&CK C0062](https://attack.mitre.org/campaigns/C0062/) 该案例支持把人机分工记入活动画像的现实相关性，但公开报告没有共同遥测下的反事实对照，不能证明 Agent 已使既有活动关联方法失效。

据此，当前论文问题收窄为：**在可观测攻击行为中加入执行方式信息，能否改善活动关联？** 识别是提供此上下文的前置能力；是否产生关联收益必须单独测量。现有公开数据只允许用 CTF 同题检索作为代理实验，不能直接检验同一真实 Campaign 的跨执行方式关联。

## 本地识别模型比较

在 CTH 固定子集上，以 `benchmark/task_id` 做五折 `GroupKFold`，同一任务的所有轨迹只出现在一折。特征限于命令名、粗动作类别和固定计数/比例，不输入题目文本、提示词、时间戳、路径、采集文件名或模型来源。每个任务在所属基准内等权；三个基准再等权宏平均。区间为固定折外预测上的 5,000 次基准分层任务簇 bootstrap，**不包含重新训练不确定性**。共 177 条轨迹、40 个任务组；分类目标是该发布中的记录标签。

| 输入与分类器 | 平衡准确率（95% 任务簇区间） | Macro-F1（95% 区间） | ROC-AUC（95% 区间） | Brier（越低越好） | ECE-10（越低越好） |
|---|---:|---:|---:|---:|---:|
| 命令名 TF-IDF 1–2gram + 逻辑回归 | **0.844** [0.766, 0.915] | **0.804** [0.709, 0.892] | **0.957** [0.914, 0.992] | 0.125 [0.107, 0.144] | 0.161 [0.132, 0.218] |
| 粗动作类别 TF-IDF 1–2gram + 逻辑回归 | 0.777 [0.692, 0.855] | 0.729 [0.638, 0.820] | 0.835 [0.757, 0.911] | 0.166 [0.149, 0.183] | 0.150 [0.108, 0.231] |
| 命令数 + 动作比例 + 逻辑回归 | 0.622 [0.569, 0.683] | 0.537 [0.477, 0.609] | 0.819 [0.734, 0.900] | 0.203 [0.181, 0.225] | 0.138 [0.103, 0.202] |
| 命令数 + 动作比例 + ExtraTrees | 0.723 [0.654, 0.797] | 0.668 [0.593, 0.751] | 0.819 [0.738, 0.895] | **0.169** [0.145, 0.194] | **0.073** [0.070, 0.163] |

命令名 TF-IDF 在区分这些**记录来源标签**上取得最高平衡准确率和 AUC；ExtraTrees 的 Brier / ECE 点估计更低。没有任何模型经过单独的概率校准流程，故 Brier / ECE 是原始概率输出的评分，不能据此宣称概率已经校准。由于类别与日志接口一一对应，这个模型排名不等于“识别执行者”的现实排序。

| 比较器 | 原生输出 | 本轮是否实测 | 复现结论 |
|---|---|---|---|
| 本地 TF-IDF / ExtraTrees | 类别得分；可在同一折外预测上测分离能力和误差 | **是**，上表 | CPU 即可运行。命令 TF-IDF 是本轮最强分离基线；概率校准仍需在独立校准集上做。 |
| OpenAI Decisions | 固定类别选择，并返回各选项 probability 与单独的 confidence；官方示例为 `gpt-6-luna` | **否** | [官方文档](https://developers.openai.com/api/docs/guides/decisions)提供接口说明。本环境无 API 凭证或可核验的免费额度，未发请求、无实测分数。 |
| Jev / TypeSafe Choice | 返回所选类别、各选项 probability 和单独的 confidence | **否** | [Choice 文档](https://docs.typesafe.ai/primitives/choice)提供接口说明；没有可核验的免费额度或账户余额，因此未调用、无实测分数。 |
| 预训练语义编码器 | 可作为命令序列语义表征基线 | **否** | 本地没有已缓存的编码器权重或对应推理运行时；本轮不下载大模型，结果表不填模拟分数。 |

OpenAI / Jev 的类别概率与 confidence 是不同输出；若后续获得合规访问条件，应在相同任务隔离、相同输入字段和同一测试集上比较零样本、等量少样本和监督学习，并分别评估 Brier、ECE、拒判覆盖率、延迟及实际费用。只比较一个 API 的最好一次调用会引入选择偏差。[OpenAI Decisions 文档](https://developers.openai.com/api/docs/guides/decisions)明确同时返回 `probabilities` 和 `confidence`；[TypeSafe Choice 文档](https://docs.typesafe.ai/primitives/choice)也将二者分别定义。

## 关联主张的压力检验

固定数据上的事后条件置换诊断运行 999 次：每个外层折只在训练任务内部置换记录标签，保持每个任务的人类/Agent 数、外层划分、候选集合和配对真值不变；每次重新拟合嵌套任务折外模式头与关联排序器。

| 候选库协议 | 真实标签下 Mode − Similarity 的 ΔRecall@1 | 置换值中央 95% 参考区间 | 置换值 ≥ 观察值 |
|---|---:|---:|---:|
| 历史候选库 | +0.068 | [−0.040, +0.056] | 5 / 999（+1 校正上尾比例 0.006） |
| 仅留出任务候选库 | −0.006 | [−0.025, +0.006] | 323 / 999（0.324） |

历史候选库的观测增量高于多数条件置换结果，但严格留出候选库没有对应增量。这个诊断是在主结果后提出的，任务内标签能否交换也没有被数据设计保证；类别仍与采集方式完全重合。因此 0.006 是条件置换分布中的经验比例，**不是有效的因果检验或通常意义的显著性 p 值**。结果也没有改变主结论：在当前数据上，执行模式没有显示出稳定、特异的活动关联收益。

当前证据支持将执行方式作为活动行为画像的**候选上下文变量**来研究，也显示任务留出下的记录标签可被命令特征预测；它没有证明 Agent 造成真实攻击活动关联错误，也没有证明参与识别可修复此类错误。下一项有决定性的实验仍需同一外部遥测采集人类、脚本、受监督 Agent 和自主 Agent 运行，并独立标注活动 ID 与执行方式。
